# Designated Target Selection

Designated Target Detection (DTD) selection creates a Space-Time Matrix (STM)
for known, externally supplied targets. In DePSI this workflow is used to load
the Radar Coding Toolbox output for designated targets and extract the
corresponding SLC pixels from a coregistered SLC stack.

The workflow consists of two steps:

1. Load the Radar Coding Toolbox CSV with `depsi.io.read_rcs_csv`.
2. Select the corresponding SLC pixels with
   `depsi.classification.designated_target_selection`.

The Radar Coding Toolbox performs target identification and radar coding at
subpixel level. Its output CSV contains the target identifiers, radar
coordinates, geographic coordinates, height, RCS validation flag, and
acquisition-dependent existence flags. DePSI converts this CSV into an
`xarray.Dataset` that can be used directly for designated target selection.

## Radar Coordinate Assumption

The target radar coordinates must be expressed in the same azimuth/range
coordinate system as the input SLC stack. For example, if the target database
was generated by Radar Coding Toolbox subpixel identification from a DORIS
cropped stack, the `slcs` dataset used in DePSI should represent that same
cropped stack or use matching radar coordinates.

Targets outside the spatial extent of the SLC stack are discarded during
selection.

### Cropped and Original Stack Coordinates

When the Radar Coding Toolbox is run on a cropped stack, the exported radar
coordinates may be expressed in the local coordinate system of the cropped
stack. In that case, the azimuth and range values are measured relative to the
first line and first pixel of the crop.

If the SLC stack used in DePSI is labelled with the original, uncropped radar
coordinates, the Radar Coding Toolbox coordinates must first be shifted to the
same coordinate system:

```text
azimuth_original = azimuth_cropped + first_line
range_original   = range_cropped   + first_pixel
```

For DORIS cropped stacks, `first_line` and `first_pixel` are stored in the crop
metadata files:

```text
nlines_crp.txt:
<number_of_cropped_lines>
<first_line_in_original_image>
<last_line_in_original_image>

npixels_crp.txt:
<number_of_cropped_pixels>
<first_pixel_in_original_image>
<last_pixel_in_original_image>
```

The important requirement is not whether the coordinates are cropped or
original-stack coordinates, but that `targets` and `slcs` use the same
azimuth/range convention before calling `designated_target_selection`.

### Subpixel Sample-Coordinate Convention

The goal of designated target selection is to assign the SLC `complex`,
`amplitude`, and `phase` values to a designated target using its precise
subpixel radar coordinates.

The SLC stack stores measurements at discrete integer radar sample coordinates,
for example:

```text
..., 3279, 3280, 3281, ...
```

The Radar Coding Toolbox returns a continuous position in this same sample
coordinate space. For example, a target may have:

```text
azimuth = 3280.244246
range   = 25800.193768
```

When this fractional coordinate is mapped to an actual SLC sample, the nearest
integer radar sample should be selected:

```text
(3280.244246, 25800.193768)
        -> nearest
(3280, 25800)

(3280.244246, 25800.793768)
        -> nearest
(3280, 25801)
```

A lower-left pixel-cell interpretation can suggest using `floor`, but that
mixes two coordinate conventions. If cell boundaries are described by
lower-left coordinates, sample locations are shifted by half a pixel. Therefore:

```text
floor(radar_coordinate + 0.5)
```

is equivalent to selecting the nearest radar sample.

For this reason, DePSI uses nearest-neighbor selection:

```python
slcs.sel(
    azimuth=targets["azimuth_subpixel"],
    range=targets["range_subpixel"],
    method="nearest",
)
```

This should not be replaced by a direct `floor()` of the Radar Coding Toolbox
coordinates.

## Example

```python
from depsi.classification import designated_target_selection
from depsi.io import read_rcs_csv

# Load the Radar Coding Toolbox output.
# A small example file is included in the DePSI repository.
targets = read_rcs_csv("tests/data/s1_dsc037_RC.csv")

# `slcs` should be an xarray.Dataset with dimensions:
# ("azimuth", "range", "time")
#
# It should correspond to the same radar coordinate system used by the
# Radar Coding Toolbox output.
dtd_stm = designated_target_selection(slcs=slcs, targets=targets)
```

The resulting `dtd_stm` is an `xarray.Dataset` with dimensions
`("space", "time")`. The `space` dimension contains the designated targets
that fall within the SLC stack extent, and the `time` dimension follows the
acquisition epochs of the SLC stack.

The output preserves the selected SLC pixel coordinates as `azimuth` and
`range`, and stores the original subpixel target coordinates as
`azimuth_subpixel` and `range_subpixel`.

## Output Dataset

The selected STM contains coordinates such as:

- `time`: acquisition epochs
- `space`: designated target index
- `target`: target identifier
- `azimuth`: nearest selected SLC azimuth coordinate
- `range`: nearest selected SLC range coordinate
- `azimuth_subpixel`: original subpixel target azimuth coordinate
- `range_subpixel`: original subpixel target range coordinate

It also contains target metadata and selected SLC variables such as:

- `lat`
- `lon`
- `height`
- `validation`
- `existing_flag`
- `complex`
- `amplitude`
- `phase`
- `h2ph`, when available in the input SLC stack
